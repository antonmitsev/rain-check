# RainCheck — архитектура v0.1

## 1. Компоненти

```text
Browser (React + Vite)
  ├── Geolocation API ──> latitude / longitude
  ├── city fallback ────> Geocoding API ──> latitude / longitude
  └── Weather client ───> Open-Meteo Forecast API
                             │
                             ▼
                     Rain evaluation logic
                             │
                             ▼
                       Bulgarian answer
```

MVP е клиентско приложение без backend и без LLM. По-късно може да се добави отделен backend за AI формулировки, без да се излагат API ключове в браузъра.

## 2. Метеорологични данни

Примерна заявка (координатите са демонстрационни за София):

```http
GET https://api.open-meteo.com/v1/forecast?latitude=42.6977&longitude=23.3219&current=rain,showers,precipitation&hourly=precipitation,precipitation_probability&forecast_days=2&timezone=auto
```

- `current.rain`, `current.showers` и `current.precipitation`: текущи стойности за валеж, според дефинициите на доставчика.
- `hourly.precipitation`: почасова прогноза за количеството валеж.
- `hourly.precipitation_probability`: вероятност за валеж, когато е налична.
- `hourly.time`: часовете в локалната часова зона, поискана чрез `timezone=auto`.

Проверявай актуалната схема и лицензионните условия на [Open-Meteo](https://open-meteo.com/en/docs), преди имплементация и публично внедряване.

## 3. Алгоритъм за двата бутона

### „Вали ли?“

1. Взимаме последните текущи данни.
2. Ако `rain > 0` или `showers > 0`, отговаряме „Според текущите метеоданни в района вали“.
3. Ако няма такива валежи, отговаряме „Според текущите метеоданни в района не вали“.
4. Ако стойностите липсват, не гадаем, а показваме неуверен отговор.

### „Докога ще вали?“

1. Ако текущите данни не показват валеж, казваме това директно.
2. Иначе обхождаме почасовата прогноза от следващия часови интервал.
3. Търсим първия интервал с прогнозен валеж под избран праг (начално: `0.1 mm/h`) **за два последователни часа**.
4. Показваме приблизителния начален час на този интервал, например „около 17:00 ч.“.
5. Ако не намерим такъв интервал, казваме, че не можем да определим надежден час в прогнозния хоризонт.

Прагът, двучасовото правило и връзката между почасови количества и локални превалявания са начални продуктови допускания за тестване, а не гаранция за точност. Почасовата прогноза не позволява прецизно обещание за минутата на спиране.

## 4. Производителност и кеш

- Кеш по закръглени координати (примерно 2 знака) и timestamp.
- TTL: 10 минути.
- Една метеорологична заявка е достатъчна за двата въпроса.
- При грешка: видимо съобщение и възможност за повторен опит.

## 5. AI опция (след MVP)

Безплатният ChatGPT план не предоставя безплатен програмируем API за собствен сайт. OpenAI API се заплаща отделно. При бъдеща интеграция: клиент → backend → API, с ограничение на заявките и защитен ключ. За MVP отговорите се генерират с локални шаблони, без AI заявки.
